# Один банк обоев на все машины

`manifest.txt` рядом — это список имён файлов, а не сами картинки.

## Почему так, а не картинками в репозиторий

Банк на рабочей машине — 685 файлов и 2 ГБ. Положить их в git можно ровно один раз: дальше они останутся в истории навсегда, каждый клон будет тянуть их целиком, а любая пересборка банка добавит сверху ещё столько же. Git хорош в текстах и плох в двоичных файлах, которые меняются целиком.

Помогает свойство самого wallhaven: **имя файла однозначно задаёт ссылку.** Первые два символа идентификатора становятся каталогом:

```
wallhaven-l3jvmp.jpg  →  https://w.wallhaven.cc/full/l3/wallhaven-l3jvmp.jpg
```

Значит достаточно списка имён — 685 строк, двадцать килобайт. Картинки каждая машина доносит сама, и банк везде получается один и тот же.

## Как пользоваться

На машине, где банк полный:

```bash
design wallpapers --export     # записать список в walls/manifest.txt
git add walls/manifest.txt && git commit -m "walls: свежий банк" && git push
```

На остальных машинах:

```bash
design wallpapers --sync       # донести недостающее по списку
```

На Windows то же самое делает [walls.ps1](https://github.com/kubeengineering/kubee-tools) из `kubee-tools`:

```powershell
powershell -File C:\code\kubee-tools\walls\walls.ps1 -Sync
```

Он же ставит картинку **одну на все мониторы** — на фоне видео экраны не должны отличаться друг от друга, а Windows по умолчанию охотно раскладывает по разным.

## Чего это стоит

Если wallhaven когда-нибудь удалит картинку, ссылка умрёт. На машинах, где файл уже скачан, он останется; синхронизация просто скажет, сколько строк не отдалось. Картинки, попавшие в банк не с wallhaven, в список не идут — из их имён ссылку не собрать, о них команда сообщает отдельной строкой.
